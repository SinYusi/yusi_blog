# 0008. Gemini 리뷰를 Codex 코드 리뷰로 교체

- 상태: 승인
- 날짜: 2026-09-29

## 배경

[ADR-0003](0003-ai-code-review.md)에서 CodeRabbit과 함께 Gemini API로 직접 구현한 리뷰 워크플로를 두 번째 리뷰어로 두었다. 사흘간(PR 10여 개) 운영한 결과는 다음과 같았다.

- **실행 안정성:** 리뷰 실행 22번 중 11번이 실패했다. 대부분 모델 과부하(HTTP 503)였고, 재시도(최대 3회)로도 해결되지 않았다. 무료 한도(하루 20회)에서는 실패한 요청도 부담이 된다.
- **리뷰 효과:** 구체적인 코드 지적은 #10의 2건뿐이었고, 나머지는 칭찬 위주의 요약이었다. 같은 기간 실제 버그(동시 마이그레이션 충돌, 마이그레이션 대상 DB 검사 누락, 운영 빌드가 시드 단계에서 실패하는 문제)는 모두 CodeRabbit이 찾았다.
- **유지 비용:** 리뷰 스크립트, 프롬프트, 워크플로, API 키와 모델 변수를 직접 관리해야 했다.

## 선택지

1. **Gemini 유지, 모델만 교체:** 과부하가 덜한 모델로 바꿔 볼 수 있지만, 리뷰 품질(지적이 거의 없음) 문제는 그대로 남는다.
2. **CodeRabbit만 사용:** 가장 단순하다. 다만 한 도구의 관점에만 의존하게 되고, CodeRabbit 시간당 한도에 걸리면 리뷰를 받을 방법이 없다.
3. **ChatGPT Codex 코드 리뷰:** GitHub 앱으로 연결하고 `@codex review` 코멘트로 요청한다. 코드와 설정을 직접 관리하지 않아도 되고, 개인 ChatGPT 요금제의 Codex 사용량으로 동작한다.

## 결정

Gemini 리뷰 워크플로를 제거하고 Codex 코드 리뷰를 두 번째 리뷰어로 쓴다.

- 도입 확인(#25): 요청 후 약 3분 만에 리뷰가 달렸고, CodeRabbit이 짚지 않은 문제(시드를 다시 실행할 때마다 `updated_at`이 바뀌어 sitemap의 수정 시각이 틀어지는 문제)를 찾았다.
- Codex는 GitHub에서 P0·P1 수준의 문제만 지적한다. 요약과 스타일 지적은 CodeRabbit이 맡고, Codex는 동작 오류를 찾는 역할로 나뉜다.
- 자동 리뷰는 끄고 코멘트로만 요청한다. 쌓인 PR(stacked PR)까지 모두 리뷰해 사용량을 빨리 쓰는 것을 막기 위해서다.
- 리뷰 규칙(한국어, 중점 항목)은 저장소 루트 `AGENTS.md`의 `## Code Review Rules` 절에 둔다.

## 결과

- `.github/workflows/gemini-review.yml`, `.github/gemini-review/`를 삭제하고, 저장소 secret `GEMINI_API_KEY`와 변수 `GEMINI_MODEL`도 지운다.
- 머지 전 필수 리뷰는 코드 변경이면 CodeRabbit + Codex, 문서만 바꾸면 Codex다 (docs/CONTRIBUTING.md 5단계).
- Codex 사용량은 ChatGPT 요금제에 따라 달라지고 저장소에서 확인할 수 없다. 한도에 걸리면 CodeRabbit 리뷰만으로 진행하고, PR에 그 사실을 남긴다.
- 리뷰 워크플로를 직접 만든 경험(구조화된 출력, 줄 번호 검증, 재시도)은 ADR-0003과 커밋 이력에 남는다.
