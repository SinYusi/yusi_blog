# 0009. 관리자 인증: Auth.js + GitHub OAuth, JWT 세션

- 상태: 승인
- 날짜: 2026-09-30

## 배경

2단계 CMS의 모든 쓰기 기능은 작성자 1인만 쓸 수 있어야 한다. 공개 페이지는 정적 생성(Cache Components)을 유지해야 하고, 인증 코드가 공개 페이지 번들이나 렌더링에 섞이면 안 된다. 미리보기 배포는 누구나 주소를 알 수 있으므로 관리자 기능을 열지 않는다.

## 선택지

1. **Auth.js v5 (next-auth 5 beta) + GitHub OAuth, JWT 세션**: DB 테이블 없이 암호화된 쿠키로 세션을 둔다. peerDependencies에 Next 16이 포함되어 있다. 단, 5.0은 아직 beta다.
2. **Better Auth**: 안정 버전이고 Drizzle 어댑터가 있다. 대신 사용자·세션·계정 테이블이 필요해 관리자 1명을 위해 스키마와 마이그레이션이 늘어난다.
3. **직접 구현 (GitHub OAuth + iron-session)**: 의존성이 가장 적다. OAuth state·PKCE·쿠키 보안을 직접 관리해야 해서 실수 여지가 크다.

## 결정

Auth.js v5를 쓰고, 버전을 정확히 고정한다(`5.0.0-beta.32`). 사용자는 1명이므로 DB 없는 JWT 세션으로 충분하다.

- **허용 계정**: GitHub 숫자 ID(`ADMIN_GITHUB_ID`)로 비교한다. 사용자 이름은 바뀔 수 있다. 허용되지 않은 계정은 `signIn` 콜백에서 거부해 세션 쿠키 자체가 만들어지지 않는다.
- **최소 권한**: OAuth scope는 `read:user`만 요청한다. 이메일은 쓰지 않는다.
- **두 겹 확인**: `proxy.ts`(Next 16에서 middleware가 이름을 바꿈)가 세션 쿠키의 GitHub ID를 확인해 로그인 화면으로 보낸다. DB는 조회하지 않는다(ADR-0005). 관리자 데이터를 다루는 페이지와 서버 액션은 `requireAdmin()`으로 다시 확인한다.
- **Cache Components**: 세션을 읽는 컴포넌트는 `<Suspense>` 안에 둔다. 관리자 경로는 부분 사전 렌더링되고, 공개 경로는 정적 생성이 그대로다.
- **배포 환경**: 인증 환경 변수는 운영(Production)과 로컬에만 둔다. 변수가 없는 배포(미리보기)에서는 `/admin`과 `/api/auth`를 404로 둔다. GitHub OAuth 앱의 Redirect URI는 운영과 `localhost:3000` 두 개이고, 와일드카드는 쓰지 않는다.

## 결과

- 스키마 변경 없이 인증을 추가했다. 공개 페이지 클라이언트 번들에 인증 코드가 포함되지 않는다(빌드 결과 검사).
- 미리보기 배포에서는 관리자 기능을 확인할 수 없다. 관리자 기능은 로컬에서 확인하고, 운영에서 최종 확인한다.
- beta 버전이므로 업데이트할 때 변경 내역을 확인한다. 세션 형식은 Auth.js 내부 형식이라, 라이브러리를 바꾸면 다시 로그인해야 한다(사용자 1명이라 부담이 작다).
- 세션은 7일 뒤 만료된다. 서버에서 세션을 강제로 끊으려면 `AUTH_SECRET`을 바꾼다.
