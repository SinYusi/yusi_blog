# 0015. 검색: 공개 글 색인을 브라우저에서 검색

- 상태: 제안
- 날짜: 2026-10-15

## 배경

3단계에서 글 검색(⌘K 창, 모바일 전체 화면)을 만든다(DESIGN.md 화면 목록). SPEC은 "Postgres 전문 검색, 디바운스, 결과 하이라이트"로 적었지만 구현 전에 다시 따진다.

- 글 수는 수십 개 수준이고 천천히 는다(1인 블로그).
- 검색어와 글은 대부분 한국어다. 한국어는 단어 뒤에 조사가 붙어("렌더링을", "렌더링이") 띄어쓰기 단위로 나누면 같은 말이 다른 단어가 된다.
- 공개 페이지는 정적 생성 + 저장 시 갱신(ADR-0013)이고, DB(Neon)는 쓰지 않으면 잠들었다가 첫 요청에 깨어난다(ADR-0005).
- 공개된 글만 찾아야 한다(초안·예약 글 제외).

## 선택지

1. **Postgres 전문 검색(`tsvector`)**: SPEC의 원래 계획. 순위·하이라이트(`ts_headline`)를 DB가 해 준다. 하지만 한국어 사전·형태소 분석이 없어 `simple` 설정으로는 조사가 붙은 말이 따로 색인되어 "렌더링"으로 "렌더링을"을 찾지 못한다. 확장(형태소 분석기)은 Neon에서 쓸 수 없다. 검색마다 서버 함수와 DB가 깨어난다.
2. **Postgres 부분 일치(`pg_trgm` + `ILIKE`)**: Neon이 지원하는 확장. 부분 문자열이라 조사 문제가 없다. 검색마다 서버 함수와 DB를 깨우고(첫 요청 지연), 순위는 직접 만들어야 한다. 글이 적은 지금은 색인 없이도 충분해 확장의 이점이 작다.
3. **브라우저 색인**: 공개 글의 제목·요약·태그·본문 글자를 JSON 하나로 만들어 두고(정적 생성, 글 저장 시 함께 갱신), 검색 창을 처음 열 때 받아 브라우저에서 부분 일치로 찾는다. 키를 누를 때마다 서버를 부르지 않아 즉시 응답하고 DB를 깨우지 않는다. 부분 일치라 조사 문제가 없다. 대신 색인 크기가 글 본문 양에 비례해 커진다.
4. **외부 검색 서비스(Algolia 등) 또는 빌드 시 정적 색인(Pagefind)**: 서비스는 무료 한도·계정·색인 동기화가 늘어난다. Pagefind는 빌드 결과 HTML을 색인하는데, 이 블로그의 글은 배포 뒤 CMS에서 바뀌므로 빌드 시 색인이 금방 낡는다.

## 결정 (제안)

3번 **브라우저 색인**을 추천한다.

- 색인: Route Handler(`/search-index.json`)가 공개 글 목록(`'use cache'`, `posts` 태그)으로 `{ slug, title, summary, tags, text }[]`를 만든다. `text`는 본문 HTML에서 태그를 걷어낸 글자이고, 글마다 앞부분 일정 길이로 자른다. 글 저장 시 RSS·sitemap과 함께 갱신된다.
- 검색: 검색 창을 처음 열 때 색인을 받는다(글 페이지의 첫 화면 JS·데이터에는 넣지 않음). 검색어를 공백으로 나눠 모든 조각이 들어 있는 글을 찾고(대소문자·유니코드 정규화 후 부분 일치), 제목 > 태그 > 요약 > 본문 순으로 점수를 매긴다. 라이브러리 없이 시작한다.
- 결과: 제목, 요약(또는 일치한 본문 주변 글자), 태그. 일치한 글자를 `<mark>`로 표시한다.
- 글 목록의 태그 필터(DESIGN.md)는 태그 페이지가 이미 있으므로 이 결정과 따로 다룬다.

## 결과

- 얻는 것: 키 입력마다 즉시 결과, DB·서버 함수 호출 없음(Neon 깨우기·비용 없음), 한국어 조사 문제 없음, 의존성 없음.
- 감수하는 것: 색인 크기가 글 수·본문 길이에 따라 커진다. 본문을 글마다 앞부분만 넣어 상한을 두고, 색인이 커지면(예: 압축 전송 100KB 초과) 본문을 빼거나 2번(서버 검색)으로 옮긴다. 형태소 분석이 없어 "렌더링했다"로 "렌더링"을 찾는 식의 활용형 일치는 부분 일치에 맡긴다.
- SPEC의 검색 항목("Postgres 전문 검색", "검색 결과 동적 렌더링")은 이 ADR이 승인되면 함께 고친다.

### 결정이 필요한 질문

1. 색인에 본문 글자를 넣을까(제목·요약·태그만 넣으면 색인이 아주 작지만 본문 내용으로는 못 찾음)? 추천: 글마다 앞 2,000자.
2. 검색 결과 페이지(`/search?q=`)도 둘까, 검색 창(⌘K)만 둘까? 추천: 창만(검색 엔진 색인 대상이 아니고, 공유할 필요가 적음).
