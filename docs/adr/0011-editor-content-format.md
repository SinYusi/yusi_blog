# 0011. 에디터 본문 저장 형식과 HTML 생성

- 상태: 승인
- 날짜: 2026-10-02

## 배경

ADR-0002에서 본문을 에디터 JSON(`posts.content`)과 렌더링된 HTML(`posts.content_html`)로 함께 저장하기로 했다. 2단계에서 Tiptap 에디터를 붙이면서 네 가지를 정해야 한다.

- HTML을 어디서 만드는가 (브라우저의 `editor.getHTML()` 또는 서버)
- 서버에서 만든다면 어떤 도구로 JSON을 HTML로 바꾸는가
- 목차에 쓰는 소제목 `id`를 어떻게 정하는가 (1단계 본문 규칙: `<h2 id>`, seed-data.ts 상단 주석)
- 에디터 코드(Tiptap, ProseMirror)를 공개 페이지 번들에서 어떻게 떼어 내는가 (#37 완료 기준: 공개 페이지 JS 번들 크기가 바뀌지 않는다)

## 선택지

**HTML을 만드는 위치**

1. **브라우저에서 `getHTML()` 결과를 보낸다**: 구현이 가장 간단하다. 대신 서버가 받은 HTML이 JSON과 같은 내용이라는 보장이 없고(요청을 직접 만들면 둘이 달라진다), 본문 규칙(소제목 id 등)을 클라이언트 코드가 지켜야 한다.
2. **서버가 JSON으로 다시 만든다**: JSON만 믿으면 되고, 규칙이 서버 한 곳에 모인다. 서버에도 에디터 스키마(확장 구성)가 필요하다.

**JSON → HTML 변환 도구**

1. **`@tiptap/html`의 `generateHTML`**: 공식 방법이다. Node에서는 DOM 구현으로 `happy-dom`(peer 의존성)이 필요하다. 문자열 하나를 만들려고 브라우저 환경 전체를 흉내 내는 셈이다.
2. **`@tiptap/static-renderer`의 `renderToHTMLString`**: 같은 확장의 `renderHTML` 정의로 DOM 없이 문자열을 만든다. 텍스트와 속성 값은 이스케이프한다. 노드별로 출력을 바꿀 수 있다(`nodeMapping`).

**소제목 id**

1. **에디터가 id를 노드 속성으로 저장한다(UniqueID 등)**: 소제목 글자를 고쳐도 id가 유지된다. 대신 id가 무작위 값이라 URL 조각(`#...`)이 읽기 어렵고, 붙여넣기·복제 시 중복 처리가 필요하다.
2. **HTML을 만들 때 소제목 글자로 만든다**: 같은 문서는 항상 같은 id가 나온다. 소제목 글자를 고치면 id도 바뀐다.

**에디터 번들 분리**

1. **`next/dynamic`(또는 `React.lazy`)으로 동적 import**: 에디터 청크를 렌더링 뒤에 따로 받는다. 측정해 보니 앱에 `import()`가 하나 생기는 것만으로 Turbopack이 모든 페이지가 받는 공통 루트 청크를 둘로 나눴다. 모듈 구성은 같지만(80개) 공개 페이지마다 청크 요청이 1개 늘고 크기가 +147B(gzip +285B) 바뀌었다.
2. **글 작성 페이지에서 정적 import**: App Router는 라우트마다 클라이언트 코드를 나누므로, 에디터를 가져오는 페이지(`/admin/posts/new`)만 에디터 청크를 받는다. 에디터는 이 페이지의 주 기능이라 늦게 받을 이점이 적다.

## 결정

- **서버가 JSON으로 HTML을 만든다.** 확장 구성은 `src/lib/editor/extensions.ts` 한 곳에 두고 에디터와 서버가 같이 쓴다. 서버(`src/lib/content/editor-html.ts`, server-only)는 JSON을 이 스키마로 검사하고(`Node.fromJSON` + `check()`), 모르는 노드·마크나 잘못된 구조, 허용하지 않은 소제목 단계(h2·h3 외)는 거부한다.
- **변환은 `@tiptap/static-renderer`로 한다.** 서버에 DOM 구현을 들이지 않는다. 결과는 공개 페이지와 같은 `renderPostHtml`(정화 → 코드 하이라이트 → 목차)을 한 번 더 거치므로, 변환 단계의 실수가 있어도 허용 목록 밖의 태그·속성은 공개 페이지에 나가지 않는다.
- **소제목 id는 글자로 만든다.** 소문자로 바꾸고 문장 부호를 지우며 공백은 `-`로 바꾼다. 한글 등 모든 문자·숫자는 그대로 둔다(예: `Next.js 16의 변경 사항` → `nextjs-16의-변경-사항`). 문서 안에서 겹치면 순서대로 `-2`, `-3`을 붙이고, 글자가 없으면 `section`을 쓴다. `sec-` 접두사는 렌더링 단계가 붙이므로 저장하는 HTML에는 넣지 않는다.
- **에디터는 글 작성 페이지에서 정적 import한다(라우트별 코드 분할).** 에디터는 `immediatelyRender: false`로 브라우저에서 마운트한 뒤에 만들고, 그 전에는 같은 크기의 자리 표시를 그린다. 공개 라우트는 이 페이지의 모듈을 가져오지 않는다(`src/app/(site)`에서 에디터 코드 import 없음).
- 빈 문단과 빈 소제목은 출력하지 않는다. 에디터는 문서 끝에 빈 문단을 항상 두고, 빈 소제목은 목차에 빈 항목을 만든다.

## 결과

- 클라이언트가 보낸 HTML을 저장하지 않으므로, `content_html`은 항상 `content`에서 다시 만들 수 있다. 본문 규칙을 바꾸면 저장된 JSON으로 HTML을 다시 생성할 수 있다.
- 에디터 확장을 바꾸면 서버 스키마도 함께 바뀐다. 기존 글의 JSON에 없어진 노드가 있으면 변환이 실패하므로, 확장을 지울 때는 기존 글을 먼저 옮겨야 한다.
- 소제목 글자를 고치거나 앞쪽에 같은 소제목을 넣으면 id가 바뀌어, 바깥에서 건 `#앵커` 링크가 끊길 수 있다. 개인 블로그에서는 읽기 쉬운 id가 더 중요하다고 보고 감수한다.
- 공개 라우트의 클라이언트 청크는 `dev`와 파일 이름·크기까지 같다(로컬 `next build`의 client reference manifest 비교). 에디터 청크(약 402KB, gzip 약 126KB)는 `/admin/posts/new`에서만 받는다. 대신 이 페이지는 에디터 청크를 처음부터 받으므로 페이지 JS가 그만큼 크다. 관리자 화면에 `import()`가 필요한 기능(예: 무거운 대화상자)을 더하면 같은 루트 청크 분할이 생기므로, 그때 공개 페이지 영향을 다시 측정한다.
- `@tiptap/static-renderer`는 `@tiptap/html`보다 쓰는 곳이 적다. Tiptap 버전을 올릴 때 출력 HTML이 바뀌지 않았는지 미리보기로 확인한다.
