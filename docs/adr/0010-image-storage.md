# 0010. 이미지 저장소: Vercel Blob

- 상태: 승인
- 날짜: 2026-10-07

## 배경

2단계에서 글 본문에 이미지를 올린다(#41). 스펙은 이미지 저장소를 Cloudflare R2와 Vercel Blob 중에서 "2단계 시작 전 결정"으로 남겨 두었다. 조건은 다음과 같다.

- 개인 블로그라 이미지는 많아야 글마다 몇 장, 월 업로드 수십~수백 장이다. 공개 페이지는 `next/image`로 크기를 맞춰 보낸다.
- 배포는 Vercel Hobby, 함수 리전은 싱가포르(`sin1`)이고, 주소는 아직 `yusiblog.vercel.app`이다(커스텀 도메인은 미정, SPEC 8장).
- 업로드는 관리자 1인만 한다. 인증 변수는 운영과 로컬에만 있고 미리보기 배포는 `/admin`이 404다(ADR-0009). 그래서 업로드가 일어나는 곳은 운영과 로컬 두 곳뿐이다.

## 선택지

비교는 2026-10-07 기준 각 서비스의 공식 문서([Vercel Blob 요금](https://vercel.com/docs/vercel-blob/usage-and-pricing), [R2 요금](https://developers.cloudflare.com/r2/pricing/), [R2 공개 버킷](https://developers.cloudflare.com/r2/buckets/public-buckets/), [Vercel 이미지 최적화 한도](https://vercel.com/docs/image-optimization/limits-and-pricing))로 했다.

1. **Cloudflare R2**
   - 무료 한도가 넉넉하다: 저장 10GB/월, 쓰기(Class A) 100만 건, 읽기(Class B) 1,000만 건, 외부 전송(이그레스) 무료.
   - 대신 공개 서빙에 도메인이 필요하다. 기본 주소 `r2.dev`는 문서상 "운영이 아닌 트래픽용"이고 속도 제한이 있으며 Cloudflare 캐시를 쓸 수 없다. 운영용 공개 주소는 그 도메인을 같은 Cloudflare 계정의 영역(zone)으로 등록해야 만들 수 있는데, 이 블로그는 아직 도메인이 없다.
   - 업로드는 S3 호환 API의 서명된 URL로 브라우저에서 직접 올린다. 접근 키·버킷·CORS 설정을 직접 관리하고, Vercel과 Cloudflare 두 곳의 계정과 비밀값을 다룬다.
2. **Vercel Blob**
   - Hobby 포함 한도: 저장 1GB/월, 읽기(캐시 미스) 1만 건, 쓰기 2,000건, 전송 10GB. 한도를 넘으면 요금이 나가지 않는 대신 **30일 동안 Blob을 쓸 수 없다**(이미 올린 이미지도 서빙되지 않는다).
   - 공개 저장소의 파일은 Vercel 주소로 바로 서빙되고 CDN이 캐시한다(캐시 적중은 읽기 건수에 들어가지 않는다). 도메인이 필요 없다.
   - 저장소를 프로젝트에 연결하면 환경 변수가 자동으로 들어간다. 브라우저 직접 업로드(client upload)는 서버가 짧은 토큰을 발급하는 방식이라, 토큰 발급 전에 관리자 확인을 넣을 수 있다. 같은 계정·같은 대시보드 안에서 끝난다.
   - 저장소 리전과 공개/비공개 방식은 만든 뒤 바꿀 수 없다.

두 경우 모두 공개 페이지의 이미지는 `next/image`(Vercel 이미지 최적화)를 거친다. Hobby 한도는 변환 5,000건/월이고, 넘으면 새 이미지만 최적화에 실패해 대체 텍스트가 보인다(기존 캐시는 유지).

## 결정

**Vercel Blob 공개 저장소를 쓴다.**

- 지금 도메인이 없어 R2는 운영용 공개 주소를 만들 수 없다. R2를 고르면 이미지 때문에 도메인 구매와 Cloudflare DNS 이전이 먼저 필요하다.
- 예상 사용량(월 업로드 수십~수백 장, 저장 수백 MB 이하)은 Blob Hobby 한도 안이다. 한도에서 가장 먼저 닿을 수 있는 것은 쓰기 2,000건인데, 대시보드에서 파일 목록을 둘러보는 것도 쓰기로 집계되므로 대시보드 탐색을 줄인다.
- 계정·비밀값·설정이 Vercel 한 곳에 모인다. 1인 프로젝트에서 관리할 곳이 적은 쪽을 고른다.

환경 분리와 업로드 방식:

- **저장소 두 개**: 운영용(Production 환경에 연결, 브라우저 업로드 토큰 발급에 쓰는 읽기·쓰기 토큰 변수도 함께 추가)과 개발용(프로젝트에 연결하지 않고 로컬 전용). 저장소 수는 무제한이고 비용은 사용량 기준이라 나눠도 비용이 같다. 로컬에서 올린 시험 이미지가 운영 저장소에 섞이지 않는다. 미리보기 배포는 업로드 기능이 꺼져 있으므로 연결할 필요가 없다(대시보드가 Preview에도 함께 연결하더라도 업로드가 일어나지 않아 영향은 없다).
- **리전**: 업로드는 브라우저에서 저장소로 바로 가므로 작성자와 가까운 서울(`icn1`)로 만든다. 목록에 없으면 함수와 같은 싱가포르(`sin1`).
- **업로드**: 브라우저 직접 업로드(client upload). 서버 액션으로 파일을 받으면 요청 본문 한도(기본 1MB)와 전송 비용이 생긴다. 업로드 경로는 브라우저가 정하므로, 브라우저는 항상 `posts/` 아래 이름으로 올리고 토큰을 발급하는 라우트도 경로가 `posts/`로 시작하는지 검사해 아니면 발급하지 않는다(`remotePatterns`가 이 경로만 최적화하므로). 같은 라우트에서 관리자 확인과 파일 형식·크기 제한을 건다. 파일 이름에는 무작위 접미사를 붙여 덮어쓰지 않는다(이미지는 바꾸지 않고 새로 올린다).
- **공개 페이지 렌더링**: 본문은 HTML 문자열로 저장되고 공개 페이지는 정화한 HTML을 그대로 넣으므로(ADR-0011, `renderPostHtml`), React의 `<Image>` 컴포넌트는 쓸 수 없다. 대신 렌더링 단계(`render.ts`)에서 `<img>`마다 `next/image`의 `getImageProps()`로 같은 결과(`/_next/image` 최적화 주소의 `srcset`·`sizes`, 원본 `width`·`height`)를 만들어 속성을 바꾼다. 그래서 Vercel 이미지 최적화와 위의 한도가 그대로 적용된다. `next.config`의 `images.remotePatterns`는 이 배포에 연결된 저장소의 호스트 하나(`BLOB_STORE_ID`로 만듦)의 `posts/` 경로만 허용한다. 와일드카드(`*.public.blob.vercel-storage.com`)를 쓰면 다른 Vercel Blob 사용자의 이미지로 이 배포의 변환량을 쓸 수 있기 때문이다.
- **이미지 정보 저장**: 별도 `images` 테이블을 두지 않는다. 주소·원본 크기·대체 텍스트·캡션은 에디터 원본의 이미지 노드에 두고 글과 함께 저장한다.
- **쓰지 않는 파일 정리**: 업로드는 글 저장보다 먼저 끝나므로, 올린 뒤 이미지를 지우거나 저장하지 않고 떠나면 어느 글도 참조하지 않는 파일이 남는다. 글을 지워도 파일은 남는다. 지금은 자동으로 지우지 않는다. 1인 블로그라 쌓이는 양이 작고(글마다 몇 장), 편집 중 지운 이미지를 바로 지우면 되돌리기(Undo)나 다른 글로의 복사가 깨지기 때문이다. 대신 저장소 크기가 Hobby 한도의 절반(500MB)을 넘으면, 저장소 목록(`list()`)과 모든 글의 본문 주소를 비교해 참조되지 않는 파일을 지우는 정리 스크립트를 만든다. 업로드는 글 저장보다 먼저 끝나므로, 올린 지 7일이 지나지 않은 파일(`uploadedAt` 기준)은 쓰고 있는 중일 수 있어 지우지 않는다. 목록 조회도 쓰기 건수에 들어가므로 정기 실행보다 필요할 때 한 번 돌린다.
- **인증**: 이 프로젝트의 서버 코드가 부르는 Blob 기능은 브라우저 업로드 토큰 발급(`handleUpload`) 하나다. 저장소를 연결하면 SDK는 기본으로 OIDC(`BLOB_STORE_ID` + 자동 발급 토큰)로 인증하지만, `handleUpload`는 OIDC가 아니라 읽기·쓰기 토큰(`BLOB_READ_WRITE_TOKEN`)이 있어야 토큰을 발급한다([client upload 문서](https://vercel.com/docs/vercel-blob/client-upload)). 그래서 운영은 저장소를 연결할 때 이 토큰 변수를 함께 추가하고, 로컬은 개발용 저장소의 토큰을 `.env.local`에 직접 넣는다(이 프로젝트는 `vercel env pull`을 쓰지 않는다). 이 토큰을 지우면 업로드가 실패한다.

## 결과

- 도메인 없이 바로 이미지를 올리고 서빙할 수 있다. 업로드 구현(#41)은 공식 SDK(`@vercel/blob`)의 client upload를 따른다.
- Hobby 한도를 넘으면 30일 동안 이미지가 서빙되지 않는다. 사용량은 Vercel 대시보드의 Observability로 확인한다. 이미지가 늘거나 커스텀 도메인을 정하면 R2로 옮기는 것을 다시 검토한다. 이미지 주소는 DB의 두 곳(에디터 원본 `posts.content`의 이미지 노드, 공개용 `posts.content_html`)에 남으므로, 옮길 때는 파일 복사와 두 곳의 주소 치환이 필요하다. 특히 `content_html`은 저장할 때 `content`로 다시 만들어지므로(ADR-0011), `content`를 빠뜨리면 다음 저장 때 옛 주소가 되살아난다.
- 저장소 리전과 공개 방식은 만든 뒤 바꿀 수 없으므로 만들 때 확인한다.
