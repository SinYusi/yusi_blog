# 0013. 발행 반영: 저장 시 updateTag, 예약 글은 캐시 수명으로

- 상태: 승인
- 날짜: 2026-10-03

## 배경

공개 페이지는 `'use cache'` + `cacheLife('hours')`로 정적 생성된다. 2단계 완료 기준은 "관리자 화면에서 발행하면 공개 블로그에 즉시 반영"이다. 예약 글은 발행 시각에 저장 요청이 없으므로 따로 공개 시점을 정해야 한다.

## 선택지

1. **저장·삭제 시 캐시 무효화**: 서버 액션에서 `updateTag`(다음 요청이 새 데이터를 기다림) 또는 `revalidateTag`(오래된 화면을 한 번 더 보여 줌).
2. **예약 글 정시 공개**
   - Vercel Cron으로 주기적으로 무효화: Hobby 요금제는 하루 1번, 실행 시각 ±59분이라 쓸 수 없다([문서](https://vercel.com/docs/cron-jobs/usage-and-pricing)).
   - 공개 조회의 `cacheLife`를 "다음 예약 시각까지"로 줄이기: 정시에 가까워지지만 조회 함수마다 다음 예약 시각을 구해야 한다.
   - 지금의 `cacheLife('hours')`에 맡기기: 코드가 없고, 공개가 최대 한 시간쯤 늦는다.

## 결정

- 저장·삭제가 성공하면 서버 액션이 `updateTag('posts')`를 부른다. 공개 조회 함수는 모두 이 태그를 달고 있어 목록, 상세, sitemap, RSS, 이전 slug 리다이렉트가 한 번에 무효화된다. 글별 태그로 나누지 않는다(글 수가 적어 전체 재생성 비용이 작다).
- 예약 글은 `cacheLife('hours')`에 맡긴다. 블로그 글이 한 시간 안쪽으로 늦게 보이는 것은 문제가 되지 않는다.

## 결과

- 발행·수정·삭제·slug 변경이 다음 요청부터 공개 페이지에 반영된다.
- 예약 글은 발행 시각 뒤 대략 한 시간 안에 들어온 요청부터 보인다. 정시 공개가 필요해지면 `cacheLife`를 다음 예약 시각까지로 줄이는 방식을 먼저 검토한다(Cron은 Pro 요금제에서만 분 단위).
