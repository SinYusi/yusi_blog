# 0002. 자체 CMS와 PostgreSQL로 콘텐츠 관리

- 상태: 승인
- 날짜: 2026-09-26

## 배경

글을 어디에 저장하고 어떻게 작성할지 정해야 한다. 이 프로젝트는 블로그 운영과 함께 프론트엔드 역량을 보여주는 것이 목표이므로, 구현 난이도와 학습 가치도 함께 고려한다.

## 선택지

1. **Git 저장소의 MDX 파일:** 가장 단순하고 빠름. 작성하려면 코드 편집과 배포가 필요하고, 에디터·자동 저장 같은 구현 경험이 남지 않음.
2. **Headless CMS (Contentful, Sanity 등):** 관리 기능이 이미 갖춰져 있지만, 핵심 기능을 외부 서비스에 의존함.
3. **자체 CMS + PostgreSQL:** 에디터, 인증, 발행 흐름을 직접 구현해야 해서 작업량이 많지만, 전 과정을 설계하고 구현한 경험을 얻음.

## 결정

자체 CMS와 PostgreSQL(Drizzle ORM)을 사용한다. 에디터는 Tiptap으로 구현하고, 본문은 에디터 JSON과 렌더링된 HTML을 함께 저장한다.

## 결과

- 블록 에디터, 이미지 업로드, 자동 저장, 발행 흐름을 직접 구현한다.
- 발행 시점에 on-demand revalidation을 호출해 정적 페이지를 갱신한다.
- DB 호스팅 비용과 운영 부담이 생기므로, 무료 티어가 있는 서버리스 Postgres(Neon 또는 Supabase)를 사용한다.
- 관리자는 1인으로 제한해 인증과 권한 모델을 단순하게 유지한다.
