# 0014. 자동 저장 범위와 동시 편집 충돌 방지

- 상태: 승인
- 날짜: 2026-10-04

## 배경

작성 중인 글이 브라우저 종료나 실수로 사라지지 않아야 한다(#40). 글은 저장하는 순간 `posts` 행에 바로 반영되고, 공개 글이면 공개 페이지 캐시도 무효화된다(ADR-0013). 그래서 자동 저장을 공개 글에 그대로 적용하면 쓰는 도중의 문장이 공개된다. 또 같은 글을 두 탭에서 열어 두면, 늦게 저장한 쪽이 먼저 저장한 내용을 알리지 않고 덮어쓴다.

## 선택지

1. **자동 저장 범위**
   - 모든 글을 자동 저장: 공개·예약 글은 쓰는 도중의 내용이 공개된다.
   - 공개 글은 초안본(별도 테이블이나 열)에 자동 저장하고, 발행할 때 합치기: 공개 글도 보호된다. 대신 초안본과 공개본을 함께 읽고 비교하는 화면, 스키마 변경, 합치는 규칙이 필요하다.
   - **저장된 초안만 자동 저장하기**: 추가 스키마가 없다. 공개·예약 글과 아직 한 번도 저장하지 않은 새 글은 자동 저장하지 않는다.
2. **동시 편집 충돌**
   - 마지막 저장이 이김(지금): 구현이 없다. 덮어쓰기를 알 수 없다.
   - 편집 잠금(먼저 연 탭이 잠금): 잠금 해제·만료 처리가 필요하고, 닫지 않은 탭이 잠금을 쥐고 있게 된다.
   - **낙관적 동시성 제어**: 화면이 불러온 `updated_at`을 저장할 때 함께 보내고, 서버가 잠근 행의 값과 다르면 쓰지 않는다.

## 결정

- **저장된 초안만 자동 저장한다.** 입력이 2초 멈추면 저장하고, 발행 설정은 바꾸지 않고 초안으로만 저장한다(발행·예약은 저장 버튼으로만). 입력 오류가 있으면 저장하지 않고 상태 줄과 해당 칸에 알리며, 초점은 옮기지 않는다.
- 자동 저장은 주소(slug)와 확정하지 않은 태그 입력을 저장하지 않는다. slug는 바뀔 때마다 이전 주소 리다이렉트가 영구히 남으므로(ADR-0012), 고치는 도중의 값이 이력으로 남지 않게 저장 버튼으로만 바꾼다. 빠진 입력이 있으면 저장하지 않은 변경으로 남겨 떠날 때 경고한다.
- 저장 전후가 모두 초안이면 공개 캐시를 무효화하지 않는다(ADR-0013의 `updateTag`는 공개 결과가 바뀔 수 있는 저장에만). 초안 자동 저장이 공개 페이지 캐시를 반복해서 비우지 않게 하기 위해서다.
- 공개·예약 글과 새 글은 자동 저장하지 않는다. 대신 저장하지 않은 변경이 있으면 탭을 닫거나 새로 고칠 때 브라우저가 확인을 묻는다(`beforeunload`). 새 글은 처음 저장한 뒤부터 자동 저장된다.
- **모든 저장(직접·자동)은 낙관적 동시성 제어를 거친다.** 저장 트랜잭션이 `select ... for update`로 행을 잠근 뒤 `updated_at`을 비교하므로, 두 탭이 같은 기준으로 동시에 저장해도 뒤의 요청은 앞의 저장 결과와 비교되어 거부된다. 거부되면 덮어쓰지 않았다고 알리고 자동 저장을 멈춘다. 저장에 성공하면 서버가 돌려준 새 `updated_at`이 다음 비교 기준이 된다.

## 결과

- 초안 작성 중에는 저장 버튼 없이도 내용이 남고, 두 탭에서 편집해도 한쪽 내용이 조용히 사라지지 않는다.
- 공개 글을 고치는 동안에는 브라우저가 비정상 종료되면 저장하지 않은 내용을 잃는다. 탭 닫기·새로 고침은 확인을 묻지만, 관리자 화면 안의 링크 이동(Next.js 클라이언트 이동)은 묻지 않는다. 공개 글 편집이 잦아지면 초안본을 따로 두는 방식으로 넓힌다.
- 충돌이 나면 자동으로 합치지 않는다. 사용자가 지금 내용을 복사해 두고 새로 고쳐 최신 내용을 불러와야 한다(1인 작성자라 충돌은 탭을 두 개 열어 둔 경우뿐이다).
