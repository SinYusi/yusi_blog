# 0005. DB 호스팅: Neon

- 상태: 승인
- 날짜: 2026-09-28

## 배경

[ADR-0002](0002-self-hosted-cms.md)에서 자체 CMS와 PostgreSQL을 쓰기로 했다. 무료 범위 안에서 운영할 서버리스 Postgres 호스팅을 정해야 한다. 개인 블로그라 초기에는 방문과 글 작성이 뜸하다.

## 선택지

|                  | Neon                                          | Supabase                                                         |
| ---------------- | --------------------------------------------- | ---------------------------------------------------------------- |
| 무료 DB 용량     | 프로젝트당 0.5GB                              | 500MB                                                            |
| 사용하지 않을 때 | 5분 뒤 자동으로 멈추고, 요청이 오면 다시 켜짐 | 7일간 사용량이 적으면 프로젝트 일시 정지, 대시보드에서 직접 복구 |
| 브랜치           | 프로젝트당 10개 (미리보기 배포별 DB 분리)     | 무료 요금제에서 사실상 사용 불가                                 |
| 함께 주는 기능   | Postgres만                                    | 인증, 파일 저장소, 실시간 기능                                   |

(2026-09 기준 공개 요금제 정보)

## 결정

Neon을 사용하고, Drizzle ORM과 Neon HTTP 드라이버로 접근한다.

- **일시 정지가 없다.** 방문이 뜸한 초기에도 운영 DB가 끊기지 않는다. 멈춰 있다가 켜지는 첫 요청은 느리지만, 공개 페이지는 정적으로 생성하므로 방문자에게 미치는 영향이 작다.
- **미리보기별 DB 브랜치.** 스키마를 바꾸는 PR을 운영 데이터와 분리해 미리보기에서 확인할 수 있다.
- **스펙과 기능이 겹치지 않는다.** 인증(Auth.js)과 이미지 저장소는 따로 정했으므로 Supabase의 묶음 기능은 대부분 쓰지 않는다.

### 리전

Neon과 Vercel 함수를 모두 **Singapore(`ap-southeast-1` / `sin1`)**에 둔다.

- Neon 선택지에 서울 리전이 없어, 한국에서 가장 가까운 Singapore를 쓴다.
- DB는 방문자가 아니라 DB에 쿼리하는 서버(Vercel 함수) 가까이에 둔다. 방문자와 함수 사이는 요청당 한 번 왕복하지만, 함수와 DB 사이는 쿼리마다 왕복하기 때문이다.
- 함수를 서울(`icn1`)에 따로 두면 방문자와는 가까워지지만 쿼리마다 Singapore를 왕복해 오히려 느려진다.
- 공개 페이지는 정적으로 생성되어 CDN에서 제공되므로 리전의 영향을 거의 받지 않는다.

## 결과

- 연결은 Vercel의 Neon 연동으로 관리한다. 배포 환경의 `DATABASE_URL`, `DATABASE_URL_UNPOOLED`는 연동이 설정한다.
- 앱 쿼리는 HTTP 드라이버(`drizzle-orm/neon-http`)를 쓴다. 여러 쿼리를 한 트랜잭션으로 묶어야 하는 CMS 쓰기 작업은 2단계에서 WebSocket 드라이버를 추가한다.
- 마이그레이션(drizzle-kit)은 커넥션 풀러를 거치지 않는 `DATABASE_URL_UNPOOLED`를 우선 사용한다.
- DB 연결 코드는 `server-only`로 표시해 클라이언트 번들에 포함되지 않게 한다.
- 이미지 저장소는 2단계 전에 따로 정한다.
- 함수 리전은 `vercel.json`의 `regions: ["sin1"]`로 코드에 명시해, 대시보드 설정이 바뀌어도 PR로 추적되게 한다.

### DB 브랜치 운영

| Neon 브랜치             | 용도                                                                         |
| ----------------------- | ---------------------------------------------------------------------------- |
| `main`                  | 운영 (Vercel Production)                                                     |
| `preview/<작업 브랜치>` | PR 미리보기. Vercel 연동이 배포마다 자동 생성하고, 배포가 삭제되면 함께 삭제 |
| `dev`                   | 로컬 개발. 마이그레이션·시드 실험은 여기서 하고 운영 DB에 직접 하지 않는다   |

- 무료 요금제의 브랜치 한도는 프로젝트당 10개다. 고정 2개(`main`, `dev`)를 빼면 미리보기용은 8개이므로, 미리보기 브랜치가 쌓이지 않는지 주기적으로 확인한다.

### 알고 있어야 할 위험

- **리전 변경 불가**: Neon 프로젝트의 리전은 만든 뒤 바꿀 수 없다. 옮기려면 새 프로젝트로 데이터를 이전해야 한다.
- **빌드 리전**: Vercel 빌드가 함수와 다른 리전(기본 미국)에서 실행되면, 빌드 중 정적 생성 쿼리마다 대륙 간 왕복이 생긴다. 목록 조회를 한 번에 묶어 페이지 수가 늘어도 빌드 시간이 크게 늘지 않게 한다.
- **함수 리전 어긋남**: 함수 리전이 기본값으로 돌아가면 동적 요청의 모든 쿼리가 대륙 간 왕복이 된다 (`vercel.json`으로 방지).
- **Edge에서의 DB 조회**: 미들웨어는 전 세계 가까운 지점에서 실행되므로 DB를 조회하지 않는다. 2단계 인증은 미들웨어에서 세션 토큰만 확인하도록 설계한다.

### 연결 확인 결과 (2026-09-28, 로컬 → Singapore)

- 첫 요청(멈춰 있던 DB가 켜짐) 826ms, 이후 266ms (`pnpm db:check`)
- 무료 한도(컴퓨트 월 100 CU-시간, 저장 0.5GB)를 넘으면 컴퓨트가 다음 달까지 멈추므로, 사용량을 주기적으로 확인한다.
